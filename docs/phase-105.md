# Phase 105 — Release build 2.0.0

The first packaged build that files real invoices. Version bumped
`1.1.0` → `2.0.0`.

## Why major

Every prior installer shipped a till that could not fiscalize, or could
only pretend to. Phase 90 removed the mock provider from production and
flipped both defaults to real; phases 91–103 built out the real wire, the
setup gate, and the payment paths on top of it. A till upgrading from
1.1.0 does not get "more of the same POS" — it gets one that submits to
eTIMS and refuses to complete a sale it could not file. That is a
behaviour change for the operator, not a feature addition, so the major
digit moves.

## The bump itself

`package.json:3` is the **only** place a version is written. Confirmed by
grep across `src/`, `docs/`, `electron-builder.yml` and the scripts —
one hit. Nothing was hardcoded and left stale:

- `app:get-version` (`main/index.ts:2435`) returns `app.getVersion()`,
  which Electron reads from `package.json`.
- `electron-updater`'s feed is generated by electron-builder from the
  same field.

So the bump is one line and both consumers follow it.

## Pre-flight

- `npx vitest run` — **83 files / 1257 tests, 0 failures**, unchanged
  from phase-103. Run *before* packaging, not after.
- `.env` mock flags audited, since this is the release where they matter:

  ```
  VITE_MOCK_PRINTER=false
  VITE_USE_MOCK_ETIMS=false
  VITE_USE_MOCK_MPESA=false
  ```

  All three real. The file is bundled verbatim into the installer by
  `extraResources`, so its contents are the shipped defaults.

## Build

`npm run dist` — typecheck (node + web), `electron-vite build`, then
`electron-builder --win` for both targets. Exit 0.

Both guard scripts ran and passed, which is the point of having them on
this particular build:

- `postbuild` → *"✓ Confirmed: neither mock provider is in out/main."*
  The phase-90 guarantee holds: no mock fiscalization or M-Pesa code
  reached the packaged main process, so this installer cannot mint a
  `KRA-MOCK-` invoice number even if a config asked it to.
- `postdist` → *"✓ Confirmed: win-unpacked/resources/.env is bundled."*

## Two things this build is not

- **Not signed.** electron-builder logged *"no signing info identified,
  signing is skipped"* for every executable, because no certificate is
  configured. Windows SmartScreen will warn on a fresh download. This is
  the same as 1.1.0, not a regression — but it is more visible on a
  build people are being asked to install for a compliance deadline.
- **Not published.** `dist` carries no `--publish` flag, so nothing was
  uploaded to the GitHub release. `latest.yml` exists locally but no
  1.1.0 till will see 2.0.0 until it is pushed to
  `Volcha-Enterprises/rubis-pos-desktop` releases.

## Left in place deliberately

`release/` still holds `RUBIS POS Setup 1.1.0.exe` and
`RUBIS POS 1.1.0.exe` alongside the new pair. `latest.yml` now points at
2.0.0, so the stale files are inert — but they are also the only local
copy of the last shipped build, so they were not deleted.

## Not done here

fiscalization v1 done` with no tags at all; tagging a release is a
deliberate act and was left to the operator.
